## 1. Goal

Create the **RunData** serializable bag — the single runtime data holder for one run. After Sprint 2, the Run System can answer "what floor are we on, what has been cleared, what is the current spawn budget" from one place, independent of any scene or MonoBehaviour.

Sprint 2 is **data only**: no state machine changes, no spawning, no UI, no upgrades.

---

## 2. Why Sprint 2 comes after the state machine

Sprint 1 (`RunStateMachine`, committed as `a473850`) defines **where** a run is (state). Sprint 2 defines **what the run knows** (data). The state machine must exist first because:

1. `RunData` is the runtime companion of run state — the state machine says "we are in FloorActive"; `RunData` says "floor 3, budget 14.8".
2. Sprint 1 proved the transition contract (`TryTransition`, `Reset`); Sprint 2 data will eventually be reset in lockstep with `RunStateMachine.Reset()`.
3. Keeping them separate means either half can be replaced without touching the other — `RunData` never references `RunStateMachine`, and vice versa.

Design source: `ROGUELIKE_SYSTEM.md:171-214` (`RunData.cs`), mirroring the existing data-bag pattern `PlayerContext` `[EXISTS PlayerContext.cs]`.

## 3. Exact responsibilities

`RunData` OWNS (run-scoped, per-run data):

| Responsibility | Detail |
|---|---|
| Current floor number | `floor` (int, starts at 1) |
| Cleared room count | `clearedRooms` (int) |
| Current floor spawn budget | `enemyBudget` (float) |
| Budget growth rate | `enemyBudgetGrowth` (static config float) |
| Enemy stat growth rate | `enemyStatGrowth` (static config float) |
| Run reset | `StartNewRun()` — returns all fields to run-1 defaults |
| Floor advance | `AdvanceFloor()` — floor++ and budget scaling |

`RunData` does NOT own:

- Run state (`RunState` / `RunStateMachine`) — separate.
- Player stats, enemy stats, weapon data, currency — `[FUTURE]` / other owners.
- Anything scene or MonoBehaviour related — it is a plain `[Serializable]` class.

## 6. Data model

Proposed `RunData.cs` (from `ROGUELIKE_SYSTEM.md:171-214`, trimmed to plan-approved fields — run seed explicitly omitted `[PROPOSED]`):

```csharp
using System;
using UnityEngine;

[Serializable]
public class RunData
{
    [Header("Progress")]
    public int floor = 1;
    public int clearedRooms = 0;

    [Header("Spawning")]
    public float enemyBudget = 10f;         // spawn budget for current floor
    public float enemyBudgetGrowth = 1.4f;  // multiplier per floor
    public float enemyStatGrowth = 1.12f;   // health/damage multiplier per floor

    public void StartNewRun()
    {
        floor = 1;
        clearedRooms = 0;
        enemyBudget = 10f;
    }

    public void AdvanceFloor()
    {
        floor++;
        clearedRooms++;
        enemyBudget *= enemyBudgetGrowth;
    }
}
```

Fields are justified by `ROGUELIKE_SYSTEM.md:182-196` (floor, clearedRooms, enemyBudget, enemyBudgetGrowth, enemyStatGrowth). **No currency, no seed, no inventory, no meta fields** — those belong to later sprints `[FUTURE]`.

## 7. Runtime state vs static configuration

| Kind | Fields | Why |
|---|---|---|
| Runtime (mutates during a run) | `floor`, `clearedRooms`, `enemyBudget` | track live run progress |
| Static configuration (tuning constants) | `enemyBudgetGrowth`, `enemyStatGrowth` | balance knobs, currently baked as defaults per design doc |

Both live in `RunData` because the design doc models them together (`ROGUELIKE_SYSTEM.md:193-196`). A future refactor could move the two growth rates into a ScriptableObject `[PROPOSED]` — **not now**. Runtime state must never be confused with static data: `RunData` is strictly per-run, reset by `StartNewRun()`.

## 8. State machine integration points

`RunData` and `RunStateMachine` stay **decoupled**. Integration happens later (Sprint 3+):

| Future integration point | Sprint | Contract |
|---|---|---|

| `AdvanceFloor()` called when a floor clears (FloorCleared → FloorStart) | 5 | call `AdvanceFloor()` on next-floor transition |
| `Reset()` of machine + `StartNewRun()` of data together | 3 | both reset to run-1 defaults |

These are **documented contracts, not implemented in Sprint 2**.
