## 6. Architecture — the thin hub

`RunController` is a plain C# class (no `MonoBehaviour`, no `UnityEngine` dependency, no singleton, no events). It composes the two existing pieces. This mirrors the codebase's simple style (`RunStateMachine` owns its own state) — no constructor injection framework, no `[SerializeField]` wiring yet.

```csharp
public class RunController
{
    public RunStateMachine StateMachine { get; } = new();
    public RunData Data { get; } = new();

    public RunState CurrentState => StateMachine.CurrentState;
    public int CurrentFloor => Data.floor;

    public bool StartRun()
    {
        if (!StateMachine.TryTransition(RunState.FloorStart)) return false;
        Data.StartNewRun();
        return true;
    }

    public bool BeginFloor()
    {
        return StateMachine.TryTransition(RunState.FloorActive);
    }

    public void Reset()
    {
        StateMachine.Reset();
        Data.StartNewRun();
    }
}
```

Notes:
- `StartRun()` only resets data on a **successful** transition — calling it mid-run (from `FloorStart`) returns `false` and does NOT wipe the run.
- `Reset()` performs machine reset + data reset together (Sprint 2 §8 contract).
- `BeginFloor()` is the "floor setup finished" trigger the plan assigns to Run System (`ROGUELIKE_RUN_SYSTEM_PLAN.md §2` transition table row 2).
- No clear/advance/end methods yet — those belong to Sprint 5 (`AdvanceFloor` on `FloorCleared → FloorStart`) and later.
